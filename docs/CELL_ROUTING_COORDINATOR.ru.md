# Согласованное применение маршрутов и firewall

`CellRoutingCoordinator` связывает CellRoutingGuard, CellRouteTransaction и
CellNftTransaction общим приватным журналом. Это этап для **уже созданного,
фиксированного набора принадлежащих нам интерфейсов**, не полный жизненный
цикл AWG. Новые/удаляемые интерфейсы этим компонентом не обслуживаются.

Последовательность: проверить интерфейсы → защитить → записать намерение →
применить firewall → применить маршруты → проверить оба компонента → записать
общий commit → снять guard после повторной проверки. Ошибка снятия guard уже
после commit не переводит общий журнал обратно на устаревшую конфигурацию.

Если успел записаться только дочерний commit, восстановление возвращается к
последнему **общему** подтверждённому снимку. Чужой/несогласованный дочерний
журнал отклоняется. После восстановления или отката guard остаётся; явный
повторный apply подтверждённого снимка включает трафик после проверок.

Проверка интерфейсов предоставляется вызывающим кодом и должна подтверждать
их владение и конфигурацию. В текущем стенде проверяется полный AWG-снимок,
метка владения, MTU; lifecycle также проверяет адреса и rp_filter.
Опция `retainGuard: true` позволяет родительской CellNetworkTransaction
оставить защиту до подтверждения общего AWG+routes+nft commit.

## Проверки 19 сентября

Девять unit tests: общий commit; отказ маршрутов после firewall; перезапуск при
частичном дочернем commit; прерванная первая установка; чужой дочерний журнал;
неподтверждённые интерфейсы; смена набора интерфейсов; отказ снятия guard;
отказ записи общего commit; маршруты через незащищённые интерфейсы.

Изолированный AWG routing lab переведён на координатор. Прежняя матрица прошла.
Дополнительный тест записал общее намерение, применил только новую firewall-
политику и создал новый координатор с теми же файлами. Восстановились прежние
маршруты и политика, трафик остался закрыт до явного apply, после чего IPv4/IPv6
заработали. Результат не означает проверку power-loss/fsync физического диска.

## Следующие границы

Межпроцессный lock, полный манифест владения AWG и его конфигурацией, создание/
удаление/перенастройка интерфейсов под общим журналом, boot-порядок, подписанная
доставка топологии и продуктовая интеграция. Без них система Ячеек не готова
к выпуску. Нужда в новых VPS для полевого теста будет определяться после
подготовки следующего законченного интеграционного этапа, не для каждой функции.

# Резерв служебного AWG — 5 ноября 2026

После обнаружения адреса через DHT отдельный технический TCP-транспорт
переносит **уже зашифрованные датаграммы постоянного управляющего AWG**.
TLS, сертификаты и повторное шифрование прикладных команд здесь не нужны.
Публичная BitTorrent DHT остаётся справочником, а не каналом команд.

## Реализовано

- Свежий случайный challenge и Ed25519-подписи обеих сторон. Конечная
  идентичность закреплена регистрацией; ключ промежуточного ретранслятора
  не заменяет её. Получатель допускает только зарегистрированного партнёра
  и свой фиксированный loopback-порт управляющего AWG.
- Не более одного промежуточного участника. Участники объявляют отдельную
  BEP5-тему технической ретрансляции; чужие профили/команды в DHT не помещаются.
  Ретранслятор проверяет подписанный BEP44-адрес назначения. По умолчанию
  пересылка к приватным/служебным IPv4-адресам запрещена; это не открытый
  произвольный TCP/UDP-прокси.
- До четырёх входящих соединений, общий бюджет полезных датаграмм 8 КиБ/с,
  ограниченные очереди/кадры, тайм-ауты регистрации и простоя, ограничение
  открытия соединений и запросов маршрута. Потери не создают бесконечной
  очереди и не отнимают приоритет у пользовательского VPN.
- Установщики резервируют UDP и TCP одного числового порта обнаружения;
  firewalld открывает только этот дополнительный TCP-порт в существующей
  зоне WAN, без переназначения интерфейсов и общего reload.
- Ячейка после трёх неудач проверяет доступность именно управления. Ошибка
  GeoIP или data-link при доступном управлении не включает резерв.
- Автоматическое перенаправление выполняется отдельной nft OUTPUT NAT
  таблицей только для точного исходного UDP-кортежа управляющего AWG.
  Постоянный Endpoint, ключи, AllowedIPs, пользовательские интерфейсы,
  internet-маршруты и GeoIP-политика не меняются. Обратный conntrack NAT
  сохраняет ожидаемый Endpoint при readback.
- Каждая мутация находится под установочным flock и повторной проверкой
  владения AWG. Приватный fsync-журнал позволяет снять собственное
  перенаправление после прерывания. Чужая/изменённая таблица не перезаписывается.
  `conntrack-tools` включён в образ; очищается только точный прежний кортеж.
- Каждые пять минут резерв снимается для следующей проверки прямого пути;
  потерянный мост также снимается. Сначала удаляется перенаправление, затем
  закрывается мост. Ошибка резервного компонента не останавливает VPN/poller.
- Подписанный poll сообщает только вид служебного пути. Основной узел хранит
  время последнего принятого сообщения; старое повторённое сообщение не
  обновляет запись. Одинаковое состояние записывается не чаще раза в 30 секунд.
  Сбой этой диагностической записи не блокирует настройки.
- В панели показаны прямой AWG, резервный путь с предупреждающим знаком либо
  отсутствие свежих данных. Пояснение раскрывается клавиатурой или касанием;
  отсутствие данных не превращается в «отключена» или нулевые показатели.
  Адресов, идентичностей DHT и пользовательской статистики в этом API нет.

## Проверено

1. Реальные UDP/TCP-сокеты: прямой и промежуточный путь, неизвестный отправитель,
   неверная закреплённая идентичность, неправильная роль, бюджеты и очереди.
2. Настоящий AWG-handshake через промежуточного участника, включая точный
   nft redirect при **запрещённом исходном UDP** и нелокальном адресе источника.
   Endpoint остаётся исходным; автоматический возврат снимает собственную NAT.
3. Подписанный `syncCellSettings` RPC через тот же резерв в **двух разных
   network namespace**, соединённых veth. Управляющие адреса находятся в разных
   пространствах, поэтому запрос действительно проходит AWG, а не локальный
   short circuit. Прямой UDP запрещён до setconf; запрос успешно проверен
   Основным узлом. TLS не использовался.
4. Полная Linux-регрессия: **864 успешно, 0 ошибок, 0 пропусков**, включая
   проверки ядра nft. Итоговый журнал скопирован на ноутбук.
5. Компонент статуса в Edge: 20 сочетаний пяти языков и ширин 320/768/1024/1440,
   раскрытие клавишей Enter, отсутствие горизонтального переполнения и ошибок
   console. Снимки 320 px RTL и 1440 px русского интерфейса просмотрены.

Команды для одноразового контейнера: `scripts/test-awg-technical-relay.cjs auto`
и `scripts/test-technical-control.cjs` при `AWG_DISPOSABLE_NETWORK_TEST=1`.
Первому нужны NET_ADMIN и TUN; второму дополнительно SYS_ADMIN и отключение
только контейнерных seccomp/AppArmor-ограничений для создания namespace.
На реальной ОС эти тестовые полномочия установщику не добавляются.

## Границы готовности

Это ещё не готовность релиза. Нужны расширенная диагностика Ячейки без
пользовательского наблюдения, испытание полной службы на межрегиональных VPS, завершение удаления
Ячейки, согласованное повышение версий и backup/restore. Здесь поддержан IPv4
технического адреса; отсутствие резервного пути не меняет пользовательский выход.
При запуске Ячейка сначала восстанавливает проверенное локальное состояние;
сценарий reboot при недоступном Основном узле ещё требует полной полевой
регрессии. Исправлено локальное восстановление: Ячейка воспроизводит только
ранее **применённую подписанную** ревизию после восстановления пользовательского
и data AWG под guard. Отсутствие свежего handshake при таком повторе не
блокирует локальный выход; владение интерфейсами, readback маршрутов и политики
проверяются. Новая ревизия по-прежнему требует живого data-link; никакого
переключения недоступного выхода на WAN не добавлено.
Старый TLS-прототип удалён следующим коммитом:
генератор сертификатов, TLS-listener/client и прежний TLS-стенд убраны.
Синхронизация принимает только зарегистрированное AWG-состояние v2 с явно
заданным tunnel-транспортом; неизвестный/прежний формат не переключается на TLS.
HTTPS для загрузки обновлений и GeoIP остаётся обычным внешним соединением.

Диагностические журналы сохранены локально в игнорируемом `private-test-access`.
Реальные ключи/профили клиентов в испытаниях не применялись.

# BEP 44: полевой тест изменяемой записи, 2026-10-02

Изолированный прототип `experiments/mainline-dht/mutable_probe.py` не связан с
AWG-Easy и не публикует пользовательские данные. Запись — короткий случайный
JSON-маркер; идентичность теста — разовая пара Ed25519. Место поиска вычисляется
как SHA-1 открытого ключа и фиксированной тестовой метки `salt`, поэтому оно
не меняется при обновлении содержимого. Читатель отдельно проверяет открытый
ключ, Ed25519-подпись и возрастающий `seq`.

На AMS (Ubuntu 22.04, libtorrent 2.0.5) публикация получила 6–8 подтверждений
в каждом из нескольких циклов. На MOW (Debian 11, libtorrent 1.2.9) запись
прочитана по тому же адресу и проверена по подписи: обнаружены `seq` 1, 2, 3,
4 и 5, включая изменение прикладной ревизии с 1 на 2. Оба процесса работали
без торрентов и завершились с кодом 0. Это подтверждает связь по публичной DHT
в направлении libtorrent 2.0 → 1.2, но ещё не рабочий механизм обнаружения
Ячеек.

Публикация с Debian/libtorrent 1.2.9 в двух попытках завершалась аварийно
(`std::bad_alloc`), в том числе после исправления формата секретного ключа.
Публиковать с этой сборки небезопасно; причина её аварии отдельно не доказана.
Первоначальные нулевые подтверждения на AMS объяснялись неверным форматом
секретного ключа в пробнике: libtorrent ожидает расширенный ключ из
SHA-512(seed), а не `seed || public`. После исправления публикации успешны.

Сравнение вариантов для продуктового компонента:

- `bittorrent-dht` — Node.js, BEP 44 mutable/immutable, MIT, многолетняя
  история; для mutable требуется передать Ed25519-подпись и функцию проверки.
- `@z-torrent/dht` — тоже Node.js и BEP 44, MIT, но значительно более новый
  пакет версии 0.0.x; оставлен запасным кандидатом.
- `pythonTorrentDHT` — Python 3.10+, BEP 5/51, BEP 44 не заявлен. Его
  зависимость `datrie` содержит C/Cython-код, так что «весь стек чистый Python»
  неверно. BEP 51 даёт выборку торрент-инфохешей и не заменяет адресный поиск
  подписанной записи Ячейки. Кроме того, нужен отдельный Python-процесс.

`bittorrent-dht` 11.0.12 дополнительно проверен на той же AMS с Node.js 12.22.9
и встроенным в Node модулем Ed25519. С явным набором трёх bootstrap-адресов
JS-пробник набрал 22 DHT-узла, прочёл опубликованную ранее libtorrent запись
`seq=3`, проверил несколько подписей и завершился с кодом 0. Это доказывает
межреализационное чтение именно для подписанного BEP 44. Без явного набора
bootstrap-адресов JS-пробник видел только один контакт, который затем выпадал,
и не находил запись; локальный Windows-тест тоже не набрал достаточно контактов.
Следовательно, в продуктовой реализации bootstrap и сохранение таблицы
контактов нельзя оставлять на неявных настройках библиотеки.

Тестовый JS-код находится отдельно в `experiments/mainline-dht/node-probe` и
не добавлен к зависимостям панели. Публикация из JS в публичную DHT, смена IP
с сохранением идентичности, доступность при блокировке отдельных
bootstrap-адресов и ограничения ресурсов под VPN-нагрузкой ещё не проверены.

Локальный тест `node --test local-mutable.test.mjs` в том же изолированном
каталоге подтвердил публикацию `bittorrent-dht` 11.0.12 между тремя экземплярами
на loopback, чтение по SHA-1(Ed25519 public key + salt), обновление `seq=1 → 2`
и отказ в публикации записи с неверной подписью. Это проверка механики записи,
не полевой тест публичной DHT: смена IP, отказ bootstrap-узлов, ресурсы под
нагрузкой и межреализационная публикация из JS остаются открытыми пунктами.

Никакие профильные ключи, команды управления, backup-файлы и адреса
пользователей в публичную DHT не помещались. Состояние сервиса Узлов/Ячеек
не менялось.

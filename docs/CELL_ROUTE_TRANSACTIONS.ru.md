# Транзакции маршрутов Ячеек

## Область реализации

`CellRouteOwnership` и `CellRouteTransaction` — отдельный локальный компонент
для маршрутов и policy rules, выдаваемых `CellRoutingPolicy`. Он пока **не
подключён** к продуктовому установщику, CLI и доставке настроек Ячейки.
Это не транзакция всей топологии: создание AWG-интерфейсов, их ключи и nft
политика остаются обязанностью будущего координатора.

## Владение и ограничения

- Вход — только ограниченный набор argv `ip -4/-6 route/rule add` компилятора.
  Нет shell-строк, flush, replace, произвольных таблиц и default в main.
- Таблицы 52000–52999 и приоритеты 20000–20999 не считаются автоматически
  свободными. Проверяются фактические `ip -j route show table all` и rules.
- Даже точное совпадение объекта на первой установке не даёт права присвоить
  его. Нужна запись в сохранённом журнале владения. Proto 186 (iproute2 выводит
  его как bgp) сам по себе также не является доказательством владения.
- Чужой маршрут в выделенной таблице, совпадающий host route в main или
  посторонний selector на выделенную таблицу блокируют применение.
- Неизвестные дополнительные атрибуты релевантных объектов не игнорируются.
  Известные формы Linux (`bgp`, IPv6 unreachable через `lo`, каноническое
  написание IPv6) нормализуются. Неизвестные формы требуют отдельной проверки.
- Требуется iproute2 с JSON-выводом `ip -j` для обеих семей. Если его нет,
  применение отказывает до изменений; текстовый вывод эвристически не парсится.
  Это отдельная проверка совместимости, в том числе для старых дистрибутивов
  Astra: прежний полевой harness ещё не использовал этот новый компонент.
- Чужие default/routes на WAN не удаляются. При откате не используются
  массовые операции и не заменяются конфликтующие объекты.

## Журнал и восстановление

Журнал хранит committed manifest и pending desired manifest. Запись идёт в
временный файл 0600 с fsync, rename и fsync родительского каталога на Linux.
Повреждённый журнал и слишком широкие права — ошибка, не повод начинать с нуля.
Предполагается один владеющий процесс; экземпляры внутри процесса сериализуются
по пути журнала. Межпроцессная блокировка должна обеспечиваться службой.

Порядок изменения:

1. Проверить команды и текущие конфликты.
2. Вызвать обязательный `activateGuard`, блокирующий все затрагиваемые VPN
   интерфейсы, в том числе удаляемые из новой топологии.
3. Сохранить pending до первой модификации маршрутов.
4. Повторно проверить kernel state; убрать устаревшие rules, затем routes;
   добавить нужные routes, затем rules.
5. Повторно сверить получившееся состояние, включая устаревшие объекты.
6. Сохранить committed. **Guard остаётся включённым даже при успехе.**

При ошибке выполняется попытка восстановить старый manifest. При ошибке
отката pending сохраняется для отдельного recovery, трафик остаётся закрытым.
После падения процесса `recover()` отменяет незавершённую смену, возвращая
последний committed, либо восстанавливает его пропавшие маршруты после
link-down. Чужие изменённые объекты не перезаписывает.

`guarded: true` означает только завершение маршрутной части. Координатор может
снять guard лишь после проверки AWG, nft, адресов, всех маршрутов и журнала
всей топологии. Компонент принципиально не снимает блокировку самостоятельно.

## Проверки и границы

14 новых unit tests: первичное владение, пропавшие маршруты, чужие объекты,
формы iproute2, ограничение argv, повторное применение, частичный откат,
ошибка guard, crash recovery, повреждение журнала и сериализация экземпляров.
Полный набор: 326 тестов, 323 passed, 3 skipped, 0 failed.

Изолированный Linux/AWG-стенд переведён с прямого исполнения argv на новый
компонент. Основная матрица IPv4/IPv6, Home/Guest, GeoIP, link-down/recover и
отсутствие fallback пройдена. Расширенные проверки частичного отката и
конфликта чужого маршрута также прошли: реальный частичный откат, сохранение
guard, повторное создание экземпляра из журнала, сохранность чужого маршрута
и восстановление после явного устранения конфликта.

Остаются: владение несколькими AWG-интерфейсами и nft-таблицами, транзакция
топологии целиком, process lock и стартовое восстановление службы, подписанный
формат топологии, настройка новых GUI/CLI и повторные полевые проверки. Не
объявлять этот компонент готовой системой Ячеек или основанием для релиза.

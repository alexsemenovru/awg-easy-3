# Узлы и Ячейки: полевой checkpoint 18 октября 2026

Временный стенд: чистые VPS с Arch Linux (Основной узел) и Fedora 44
(Ячейка), оба x86_64 и менее 1 ГиБ RAM. Рабочий ARN не изменялся.
Код для стенда взят из ветки `codex/cells-foundation`; тестовые образы
собраны локально на каждой VPS из закреплённых исходников AWG 3.1.
Доступы, приглашения, ключи и профили в репозиторий не добавлялись.

## Подтверждено на двух VPS

- Docker Compose прочитал оба opt-in overlay. Пользовательская панель на
  Основном узле работает и остаётся `healthy`; служебные контейнеры не
  наследуют её неуместную проверку здоровья.
- Одноразовое AWG-приглашение создало временный канал, Ячейка прошла
  регистрацию, затем обе стороны подтвердили постоянный AWG-путь.
- Ячейка применила подписанную пустую пользовательскую ревизию №1 и
  отправила подтверждение. После перезагрузок и пересоздания контейнеров
  ревизия №2 была получена и подтверждена автоматически, без ручного `sync`.
- Перезагрузка Fedora восстановила оба служебных AWG-интерфейса и
  пользовательский интерфейс Ячейки; перезагрузка Arch восстановила
  панель и оба интерфейса Основного узла. Снимок Ячеек доступен панели
  только через приватный read-only mount, а запрос API без входа даёт 401.
- Остановка только служебного контейнера Основного узла не остановила
  Ячейку: её пользовательский AWG-интерфейс, nft-политика и применённая
  ревизия №2 остались на месте. После возврата Основного узла ревизия №3
  была подтверждена автоматически. Это проверка сохранения состояния,
  не доказательство непрерывности реального клиентского трафика.

## Дефекты, обнаруженные только при живом запуске

1. `nft -j list` сгруппировал объявления цепочек отдельно от правил.
   Сравнение исходно считало это чужой таблицей и оставляло защитное
   правило включённым. Отпечаток теперь канонизирует только порядок
   объявлений и групп цепочек, сохраняя порядок правил внутри цепи;
   фактический пакет команд nft не переставляется.
2. Прерванный первый `init` оставил собственный защитный nft guard до
   создания lifecycle-журнала. `resume` теперь доказывает владение guard
   по журналу и исключает только эту таблицу из проверки свободных
   ресурсов, не присваивая чужие таблицы.
3. Docker разрешает читать `/proc/sys`, но не записывать туда из такого
   контейнера. Если новый AWG-интерфейс уже унаследовал требуемый
   `rp_filter=2`, лишняя запись пропускается; иное значение по-прежнему
   закрывает запуск до явной настройки хоста.
4. Временный каталог `/run` исчезал после перезапуска Ячейки, тогда как
   kernel nft-таблица оставалась. Без сохранённых артефактов безопасный
   readback отвергал повторный запуск. Runtime перемещён в закрытый
   постоянный каталог Ячейки `/cell-data/runtime`.
5. После reboot отсутствие handshake блокировало даже TCP-пробу, которая
   должна этот handshake инициировать. Ячейка теперь сначала делает
   пробу служебного TCP через AWG и сразу после неё требует свежий
   handshake; одна только доступность TCP не считается доказательством.
6. Изменение представления nft policy между сборками делало строгий
   JSON-сравнитель постоянного плана ложным отказом. План теперь
   сравнивает policy по тому же семантическому отпечатку nft, но не
   допускает изменений правил или маршрутов.

## Ограничения результата

Это всё ещё dev overlay, а не продуктовая установка. Первичная регистрация
выполнялась внутри временно запущенных контейнеров: краткоживущий
`docker compose run --rm` завершает фоновый процесс `amneziawg-go` и
не подходит для первоначального `init` в текущем CLI. Инсталлятор, UI
создания/отзыва Ячеек, реальный пользовательский Home/Guest-трафик,
IPv6/GeoIP на двух VPS, отказоустойчивость DHT, автообновление Ячеек и
backup/restore требуют отдельной работы до релиза.

Локальная проверка после этих исправлений: `pnpm -C src test` — 677 тестов,
639 пройдено, 38 платформенных пропусков, ошибок нет; `pnpm -C src check`
успешно. Полный комплект надо повторить перед релизом на Linux и при
продуктовой установке.

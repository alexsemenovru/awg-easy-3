# AWG-регистрация Ячейки — контрольная точка 2026-09-28

Решение пользователя: убрать самоподписной TLS из целевой прямой регистрации.
Обычное управление и регистрация должны идти внутри AWG 3.x. TLS-прототип пока
сохранён в коде как проверенный предыдущий этап, но не подключён к установщику.
FRA не менялась; VPS для этого этапа не предоставлены.

## Порядок без раскрытия постоянного ключа Ячейки

1. Основной узел резервирует уникальный внутренний адрес и создаёт временную
   пару AWG-ключей и PSK. Он знает временный приватный ключ, но не создаёт
   постоянный приватный ключ Ячейки.
2. До показа приглашения узел сохраняет намерение, устанавливает временного
   пира на *своём* служебном AWG-интерфейсе и проверяет readback. Доступ с
   временного адреса ограничен только внутренним TCP-портом регистрации;
   ни forwarding, ни панель, ни сети других клиентов недоступны.
3. Код приглашения содержит одноразовый секрет, временный приватный ключ/PSK,
   публичный ключ узла, параметры AWG 3.x, внешний endpoint, внутренние адреса
   и срок действия. На сервере хранится хеш секрета и параметры для отзыва,
   но не временный приватный ключ. Код показывается один раз и не логируется.
4. Ячейка создаёт временный AWG-интерфейс, проверяет handshake, создаёт свои
   постоянные ключи AWG и Ed25519 и отправляет подписанный запрос по туннелю.
   Узел сохраняет регистрацию перед подписанным подтверждением.
5. Постоянное соединение подготавливается и подтверждается на обеих сторонах.
   Только после этого временный пир отзывается и его служебный доступ закрывается.
   При обрыве перехода не выдавать автоматически новое приглашение или права
   старому временному пиру: восстановление должно читать журнал и закрывать
   неопределённое состояние.
6. По сроку, отзыву и после успешной регистрации временный пир должен быть
   удалён из AWG и guard; сбой удаления остаётся заметным и закрытым. Команда
   удаления не должна трогать другие пиры или чужие интерфейсы.

## Реализовано локально

- `CellAwgBootstrapInvitation` создаёт/проверяет ограниченный формат кода v2;
  ключи получает от существующего `AwgKeyManager`.
- Серверная запись не содержит временный приватный ключ и полный секрет.
- Служебные ответы подписаны, есть локальный TCP-транспорт для работы внутри
  частного туннельного адреса. Слушатель не включается автоматически.
- Регистрационный запрос и подписанная квитанция проходят такой же локальный
  транспорт без TLS; тест использует loopback, а не настоящий AWG. Старый код
  приглашения v1 в этом транспортном тесте нужен только для изоляции проверки.
- Генератор «очищенных» AWG-конфигураций временного пира проверяет IPv4/IPv6
  внутренние адреса. Клиенту разрешён только адрес регистрации `/32` или `/128`;
  DNS и маршрутов в Интернет нет. Серверный список пиров проверяется на
  дублирование и не принимает отозванные записи. Внешний nft-guard пока не создан.
- Приватное хранилище v2 сохраняет подготовку, готовность, потребление и
  закрытие временного пира. Регистрация не принимается до готовности; повтор
  того же подписанного запроса после потерянного ответа допустим. Координатор
  не отдаёт код до readback пира, закрывает неудачную выдачу и при восстановлении
  убирает незавершённую подготовку. Потреблённый временный пир нельзя снять
  без подтверждения постоянного пути. Пока runtime в тестах имитирован.
- Подготовлен отдельный nftables snapshot `awg_easy_3_bootstrap`: только
  внутренний TCP-порт регистрации для временного адреса, запрет прочего
  input/output и полного forwarding на выделенном интерфейсе. `CellNftTransaction`
  умеет работать с этой отдельной таблицей. Это пока генератор/тесты, а не
  применённая политика. Позднейшая UFW-цепочка может дополнительно блокировать
  разрешённый пакет; установщик должен добавить узкое разрешение.
  Синтаксис IPv4 и IPv6 batch проверен локальным `nft -c -j -f -` в WSL;
  реальное применение и readback пока не проверены.

## Следующие обязательные этапы

- Отдельный принадлежащий проекту AWG-интерфейс регистрации, чтобы изменение
  временных пиров не перестраивало пользовательский туннель. Проверить занятость
  имени/UDP-порта и не принимать чужой интерфейс как свой. Не запускать для него
  второй `CellNetworkTransaction` в текущем виде: тот использует общую таблицу
  `awg_easy_3_routes` и может столкнуться с уже работающей сетью Ячеек.
- Журнал транзакции для резерва адреса, установки/удаления пира, восстановления
  после краша; строгий nft guard на внутренний TCP-порт и запрет forwarding.
  При добавлении сначала установить пир под полным guard, затем разрешить
  только регистрационный порт; при удалении сначала снять разрешение, потом
  пир. Каждую фазу проверять по фактическому AWG/nft readback.
- Соединить `CellEnrollmentStore` и `CellConnectionStore` с кодом v2 и
  проверенным туннельным регистрационным транспортом. Проверить повтор запроса после
  потери подтверждения, гонку истечения срока и одноразовость.
- Переход на постоянный межсерверный AWG-пир без обрыва пользовательских
  соединений, с проверкой подписей и автономным восстановлением Ячейки.
- Интеграционные Linux/WSL-тесты настоящего AWG/nftables, затем два VPS.
  До прохождения не включать в установщик/релиз и не удалять старый прототип.

Отдельно: резервная ретрансляция при потере прямого AWG ещё требует сквозной
конфиденциальности и аутентификации. Для неё сертификаты не обязательны;
выбор формата шифрования пока открыт. DHT остаётся средством обнаружения,
а не каналом пользовательского VPN-трафика.

# Владение nft-таблицами маршрутизирующих Ячеек

Локальный компонент `CellNftOwnership` проверяет снимки JSON только двух
таблиц family inet: awg_easy_3_routes и awg_easy_3_routing_guard.
Он не принимает произвольные команды, другие таблицы или другой family.

Сравнение сохраняет правила, выражения, комментарии и содержимое наборов;
игнорирует лишь kernel handles и metainfo. Само имя таблицы не доказывает
владение. Если фактическая таблица отличается от сохранённого собственного
снимка, замена запрещена. Чужая одноимённая таблица на первой установке
также не присваивается. Пропавшую собственную таблицу можно восстановить.

План изменения состоит из одного атомарного JSON-пакета delete/add выбранной
таблицы, а не flush ruleset. При одинаковой политике выдаётся пустой план.
Это чистый планировщик: он не выполняет команды и не хранит журнал сам.
Снимки — локальные доверенные артефакты; это **не формат настроек**, который
можно принимать от клиентов или прямо из управляющего сетевого запроса.

## Проверки 19 сентября

- 6 unit tests: владение, обнаружение изменений правил/наборов, недопустимые
  объекты, атомарный план, no-op и восстановление пропавшей таблицы.
- Изолированный Linux: реальные JSON readback, замена, откат старого снимка
  с изменившимися kernel handles, набор interval IPv4 с префиксом.
- Заведомо ошибочный пакет с отсутствующей chain не уничтожил исходную
  таблицу. Посторонняя тестовая таблица также сохранилась.
- Полный JS-набор: 332 теста, 329 passed, 3 skipped, 0 failed.

`scripts/run-cell-wsl-lab.sh ... nft` запускает отдельный тест только в
изолированных mount/net/PID namespaces. Старые VPS не использовались.

## Ограничения перед общим координатором

Это ещё не crash-safe транзакция всей AWG-топологии. Нужны общий durable
журнал и стадийность guard/AWG/routes/nft, владение интерфейсами, process lock,
проверки после перезапуска, подписанный формат топологии и подключение к GUI.

Нельзя считать `nft -c -j -e` способом получить ожидаемый JSON до применения:
на проверенном nft 1.1.3 dry-run ничего не выводит. В будущем компилятор должен
выдавать ожидаемый декларативный JSON сам либо иметь другой проверенный путь
подготовки снимка. Слепое присвоение таблицы после падения между применением
и сохранением снимка недопустимо. Пока компонент в продуктовый runtime не
подключён; existing runtime не заменён.

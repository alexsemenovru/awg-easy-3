# Общая транзакция конфигурации AWG и маршрутизации

CellNetworkTransaction — родитель для уже подготовленного **фиксированного**
набора AWG-устройств. Изменение peer-конфигурации, маршрутов и nft-политики
подтверждается одним общим приватным журналом network.json.

Порядок: общий guard → проверка подтверждённого состояния → durable intent →
AWG setconf/readback → обновление lifecycle-снимков → routes/nft с сохранением
guard → проверка всех компонентов → общий commit → проверка и снятие guard.
Ошибка снятия защиты после commit не откатывает подтверждённую версию.

После прерывания сравниваются дочерние журналы с точными before/after снимками
родителя. Даже если один дочерний компонент успел записать новую версию,
восстановление возвращает последнюю общую версию. Необъяснимое изменение
не перезаписывается. После восстановления защита остаётся до явного apply.
Идентичность/ключ сервера, MTU, адреса и состав устройств здесь неизменяемы.
Это ещё не транзакция добавления/удаления Ячеек или ротации ключей.

Первичная initialize проверяет существующие lifecycle и routing commitments.
Она не усыновляет чужие интерфейсы и не разворачивает сеть с нуля.
При recover отсутствующие устройства воссоздаются через lifecycle только из
разрешённых родительским журналом снимков; прерванное создание возобновляется.
Одноимённый чужой/непомеченный интерфейс не присваивается. Последовательность
защита → устройства → AWG-снимок → маршруты/firewall сохраняется. После потери
серверного процесса клиенту может понадобиться переподключение без смены
профиля. Потеря объектов ядра в namespace не равна проверке reboot VPS.
Журнал содержит ключи: только приватный каталог 0700 и файлы 0600, atomic
rename/fsync; ошибки не должны выводить его содержимое. Требуется внешний
межпроцессный lock, библиотечная очередь защищает только один процесс.

Field harness v3 использует этот родительский журнал под системным flock.
Первое развёртывание выполняет v2, затем точный v3 bundle передаёт управление
родителю. После создания network.json старые v1/v2 команды отвергаются,
чтобы они не обходили его решения. Продуктовый установщик этим не изменён.

Модульные тесты: общий commit, отказ AWG после изменения, частичный routing
commit, новый процесс с разными дочерними версиями, отказ при постороннем
состоянии, запрет смены идентичности/адресов, ошибка общего commit и release.
Изолированный Linux-тест проверяет настоящие AWG/nft/ip и v3 в новых процессах.
Сценарий не подтверждает сохранность данных при физической потере питания.

# Устойчивый guard маршрутизирующих Ячеек

`CellRoutingGuard` — отдельный компонент защитной nft-таблицы, не готовый
координатор всей топологии. Продуктовая служба пока его не использует.

- `protect(interfaces)` сначала записывает и синхронизирует точное намерение
  в приватный журнал, затем применяет предвычисленный JSON и проверяет readback.
  Повторный вызов расширяет защиту: старые интерфейсы нельзя случайно исключить.
- `recover()` восстанавливает защиту после прерванного применения. Если процесс
  остановился при снятии guard, восстановление отменяет снятие и блокирует
  трафик до новой явной проверки всей топологии.
- `release(verifyRuntime)` требует callback, возвращающий именно `true`.
  Пропавший guard восстанавливается до callback. Ошибка финальной записи после
  удаления вызывает попытку возврата защиты; обе ошибки не замалчиваются.
- Имена таблиц сами по себе не дают владения. Допускаются только точные снимки
  предыдущего состояния и заранее сохранённого намерения. Изменённые/чужие
  правила не удаляются. Ошибки чтения nft не трактуются как отсутствие таблицы.
- Журнал 0600, atomic rename, fsync файла/каталога; повреждённые файлы,
  символические ссылки и публичные права на Linux отвергаются.

## Проверки 19 сентября 2026

11 unit tests; на Windows одна проверка Linux-прав пропускается, в изолированном
Linux прошли все 11. Реальный AWG routing lab также прошёл: после имитации
прерывания удаления новый экземпляр компонента прочитал журнал, вернул guard,
IPv4/IPv6 остались заблокированы до проверки и явного снятия. Все прежние
сценарии Home/Guest, GeoIP, семейных переключателей и отказа туннеля сохранены.

## Границы гарантий

Работа предполагает единственный владеющий процесс. Очередь сериализует
экземпляры в одном процессе, но межпроцессного lock ещё нет. Нельзя одновременно
редактировать эти таблицы внешними средствами. Проверка readback не заменяет
общую транзакцию AWG/routes/nft или гарантии сохранности диска.

После перезагрузки ОС guard должен восстанавливаться **раньше** запуска VPN;
одного существования JSON-файла недостаточно. Этот порядок ещё предстоит
подключить к службе и установщику. После успешно завершённого release общий
координатор также обязан иметь своё сохранённое состояние топологии.

Callback стенда проверяет только условия контролируемой фикстуры. В продукте
он должен проверять все интерфейсы, ключи/peer-конфигурацию, маршруты и nft-политику.
Для полной политики ещё нужен ожидаемый JSON до применения; guard решает эту
задачу только для собственной небольшой защитной таблицы.

Старые VPS не использовались; изменения основной сети WSL и профиля браузера
не требовались. Новый VPS для этого компонентного этапа не нужен.

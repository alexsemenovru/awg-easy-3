# Перенос действующего AWG-Easy-3: SOF → FRA, 20 сентября 2026

## Назначение и границы

По отдельному разрешению владельца перенесена действующая панель с SOF
`131.123.43.120` на FRA `216.57.108.77`. Это аварийная ручная миграция,
не реализация проектной backup/restore-системы и не тест Ячеек.
Оба сервера Ubuntu 24.04.5. Домен `alexsemenovru.cloud-ip.cc` уже направлен
владельцем на FRA (A и AAAA проверены).

## Сохранено

- Исходная версия `0.1.6`, точный Docker image ID
  `sha256:4a218ff42b401fd84a25c576090a42d52e204d8f3b4fd530ec352021580199ec`.
- Все 11 клиентов, их ключи, пароль панели, GeoIP-база и настройки.
- Endpoint доменный, UDP 51820; панель только на `10.8.0.1:51821`
  и `[fd35:e03:5563::1]:51821`.
- Исходная установка SOF не удалена. Остановлен только `awg-easy-3`,
  restart policy изменена на `no`, его update.timer выключен.
  Остальные контейнеры SOF не переносились и не останавливались.

## Согласованные адаптации FRA

На FRA AWG2 работает непосредственно в ОС на `awg0`, подсеть `10.9.9.0/24`,
UDP 39743. Его конфигурация сохранена; контрольная сумма полного showconf
до и после переноса совпала. Установленный модуль AWG уже версии 3.1.20260812.

Для панели выбран `awg3`, подсети и клиентские конфиги не изменены.
В state.json изменено только server.interfaceName. В перенесённых install.sh,
awg-easy-3 и установленной CLI-копии имена awg0 заменены на awg3: иначе
команда удаления могла затронуть чужой AWG2. В compose добавлен healthcheck
для awg3. Приложение внутри образа не изменялось.

По явному разрешению установлен Docker с `/etc/docker/daemon.json`:
`{"iptables":false,"ip6tables":false,"bridge":"none"}`. Для host-контейнера
панели мост не нужен. Это глобальная настройка нового Docker: будущим
bridge-контейнерам понадобится отдельное сетевое проектирование.

UFW остался включён. Добавлены только UDP 51820 на eth0, TCP 51821 со стороны
awg3 и forwarding awg3→eth0/awg3. Собственная nft-политика панели продолжает
ограничивать Guest/Home, семейства IP и GeoIP. Публичный TCP 51821 не открыт.

В `/etc/sysctl.d/99-awg-easy-3.conf` сохранены:

```ini
net.ipv4.ip_forward=1
net.ipv6.conf.eth0.accept_ra=2
net.ipv6.conf.all.forwarding=1
net.ipv6.conf.default.disable_ipv6=0
net.ipv6.conf.lo.disable_ipv6=0
```

Последние два параметра потребовались из-за исходной настройки FRA,
отключавшей IPv6 у новых интерфейсов и loopback. Существующий awg0 не менялся.
Модуль tun добавлен в owned modules-load.d/awg-easy-3.conf.

**Автообновление панели на FRA приостановлено по согласованию.** Текущий
updater отклоняет локально изменённые tracked-файлы. До следующего обновления
нужно штатно поддержать альтернативное имя интерфейса в installer/CLI/healthcheck,
перенести адаптации в поддерживаемую конфигурацию и только затем включать update.
Не выполнять слепой git reset, переустановку или возврат имени awg0.

## Резервные копии и продолжение

На обоих серверах `/root/awg-migration-20260920/awg-easy-3.tar.gz`.
На FRA дополнительно сохранены исходные UFW/iptables и state-original.json.
Архив содержит приватные ключи и парольный хеш; не публиковать и не прикладывать
к GitHub. Локальная копия находится только в игнорируемом private-test-access.
Файлы входа SOF.txt/FRA.txt и их содержимое в этот документ не включались.

Не удалять SOF до подтверждения владельца. При необходимости откат на SOF:
сначала остановить перенесённый контейнер FRA; вернуть домен и согласовать
сетевую доступность SOF; на SOF вернуть restart unless-stopped и запустить
исходный контейнер. Автообновления включать отдельно после проверки.

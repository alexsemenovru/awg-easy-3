# Проверка выпуска 0.1.2 на VPS

Этот сценарий предназначен для временного тестового VPS после его очистки. Он
проверяет не только AWG-Easy 3, но и то, что установка не повреждает уже
работающую инфраструктуру.

Часть сценариев выполнена 30 августа 2026 на Ubuntu/systemd:
[результаты и оставшиеся проверки](VPS_TEST_2026-08-30.ru.md). В том испытании
контрольным соседом был отдельный Docker-сервис, не 3x-ui.

Нужен образ из того же выпуска, что установщик и управляющий скрипт.
Использовать кандидат только после успешного workflow **Build and Push Docker
Image** для тега `v0.1.2`. Образ `0.1.1` этих изменений не содержит.
Полевые результаты в отчёте относятся к rc.2; заключительные UI-правки
проверены локально. Этот чек-лист можно повторить на новом стенде.

## 1. Подготовить контрольную точку

Установить 3x-ui, убедиться, что открывается его панель и работает хотя бы одно
тестовое подключение. Затем сохранить вывод команд:

```bash
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Ports}}'
docker network ls
ss -lntup
ip -brief address
ip route
ip -6 route
nft list ruleset
sysctl net.ipv4.ip_forward net.ipv6.conf.all.forwarding
```

Отдельно записать публичные порты 3x-ui, его контейнеры, сети Docker и имена
созданных им firewall-объектов. Выбранный UDP-порт AWG и VPN-подсети не должны
с ними пересекаться.

## 2. Установить AWG-Easy 3

На тестовом сервере, где AWG-Easy 3 ещё не установлен:

```bash
git clone --branch v0.1.2 https://github.com/alexsemenovru/awg-easy-3.git awg-easy-3
cd awg-easy-3
sudo ./install.sh
sudo awg-easy-3 status
sudo awg-easy-3 auto-update status
```

Профили, ключи и пароль из вывода установки не публиковать в отчёте.

Запустить штатный установщик без предварительной ручной установки Docker или
Compose. На поддерживаемом дистрибутиве он должен определить менеджер пакетов,
установить недостающие зависимости и запустить Docker.

Без `--port` и `AWG_PORT` должен выбираться свободный случайный UDP-порт
в диапазоне 20000–60000, кроме 51820. Сопоставить его с `awg show`, `settings`
и экспортом профиля. Проверить пропуск занятых UDP-портов, включая публикации
Docker без docker-proxy. Занятость того же номера TCP не должна мешать UDP.
При включённом облачном firewall разрешить выбранный порт вручную.

Для проверки диалога занять TCP-порт панели по умолчанию. Интерактивный запуск
без `--panel-port` должен предложить альтернативу и принять пользовательский
ввод. Повторный запуск с явно заданным занятым портом должен
остановиться с понятной ошибкой и примером свободного значения. Конфликт
подсети, интерфейса `awg0`, имени контейнера или таблицы `awg_easy_3` всегда
должен останавливать установку, не изменяя и не удаляя чужую конфигурацию.

## 3. Проверить AWG-Easy 3

- контейнер запущен и проходит healthcheck;
- наружу опубликован только выбранный UDP-порт AWG, TCP-порт панели отсутствует
  в публикациях Docker;
- первый профиль импортируется текущей AmneziaVPN через `vpn://`;
- через туннель работают IPv4 и, при наличии маршрута VPS, IPv6;
- Guest получает интернет, но не видит панель и VPN-подсети;
- два Home-клиента видят панель и друг друга;
- создание, отключение и удаление клиента применяются без перезапуска;
- после смены пароля старые сессии панели перестают работать;
- панель показывает состояние, текущую скорость, handshake и endpoint;
- после переключения телефона с Home admin на отдельный профиль сопоставить
  оба статуса и скорости с серверными RX/TX и временем handshake. Записать
  точные единицы, направление и длительность остаточного трафика;
- проверить две открытые панели, сбой API, тайм-аут, скрытие и возврат вкладки,
  перезапуск контейнера. До второй выборки показывается «Измерение…», при
  ошибке — «Данные недоступны», а не замороженная старая скорость;
- restart, повторный start и update сохраняют порт и профили. Команда settings
  читает сохранённый порт даже при остановленном VPN и не запускает VPN;
- credits видны на странице входа и в панели, доступны с клавиатуры, корректны
  на мобильном экране и при RTL; переход не отправляет внутренний Referer;
- серверная ретрансляция mDNS/SSDP проверяется захватом трафика между двумя
  реальными Home-устройствами; видимость в приложениях фиксируется отдельно
  как совместимость клиента с multicast через VPN-интерфейс.

## 4. Проверить сосуществование

Повторить контрольные команды из первого пункта и сравнить результаты. Панель
3x-ui и её тестовое подключение должны продолжать работать.

Допустимые изменения AWG-Easy 3 ограничены:

- интерфейсом `awg0` и его адресами;
- таблицей nftables с префиксом `awg_easy_3`;
- помеченными правилами AWG-Easy 3 в `DOCKER-USER`;
- собственным sysctl-файлом проекта;
- собственными контейнером, образом, volume и сетью Compose;
- выбранным публичным UDP-портом AWG.

Контейнеры, сети, правила, порты и файлы 3x-ui не должны быть изменены,
перезапущены или удалены установщиком AWG-Easy 3.

## 5. Проверить удаление

После теста удалить AWG-Easy 3 штатной командой и снова сравнить контрольную
точку. Объекты проекта должны исчезнуть, а 3x-ui — сохранить работоспособность
и свои исходные настройки.

Также должны исчезнуть только собственные systemd/OpenRC-задания обновления,
глобальная команда и указатель каталога установки. Чужие задания не меняются.

## 6. Проверить автообновление и восстановление

Проверить отдельно на systemd и, при наличии тестового VPS, OpenRC:

- функция включена после установки без вопроса; `auto-update disable`,
  `enable` и `status` работают из любого каталога;
- после перезагрузки VPN доступен до проверки обновлений; запускается одна
  отложенная проверка, а не постоянный опрос. На systemd журнал смотреть через
  `journalctl -u awg-easy-3-update.service`, на OpenRC —
  `/var/log/awg-easy-3-update.log`;
- `auto-update run` при уже установленном последнем стабильном выпуске ничего
  не меняет; с rc.1/rc.2 переход на стабильную 0.1.2 должен сохранять состояние;
- после `stop` автоматическая проверка не запускает VPN. Затем вручную `start`;
- сбой GitHub/реестра не заменяет рабочую версию, не раскрывает секреты;
- параллельные `update`/`uninstall`/`reinstall` не выполняются одновременно;
- успешное обновление сохраняет порт, клиентов, ключи, пароль и Home/Guest;
- неуспешный healthcheck либо обрабатываемое прерывание после замены версии
  возвращает прежний checkout и исходный кешированный образ.

Последние два сценария требуют следующего совместимого стабильного выпуска
либо контролируемого стенда с тестовым источником релизов. 30 августа они
пройдены с реальным Docker/Compose и локальными fixture-образами на VPS;
границы этого испытания приведены в отчёте выше. Одних локальных сценариев
с подменённым Docker недостаточно, чтобы считать их VPS-проверенными.
Не подменять публичные стабильные теги ради теста. Откат не защищает от
SIGKILL, потери питания, повреждения диска или несовместимой миграции данных.

Телефонное переключение и контролируемая остаточная отправка проверены:
см. отдельный раздел полевого отчёта. Исходный триггер видео не установлен.
OpenRC остаётся непроверенным на реальном сервере. Переключатели IPv4/IPv6
не входят в этот выпуск.

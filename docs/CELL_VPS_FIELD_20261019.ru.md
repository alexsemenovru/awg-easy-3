# Основной узел и Ячейка: продуктовый двухсерверный прогон 19 октября 2026

Стенд: чистые тестовые VPS — Rocky Linux 10.2 (Основной узел, 1,7 ГиБ RAM)
и ALT Server 10.4 (Ячейка, 0,9 ГиБ RAM). Использован один локально собранный
образ текущей ветки; рабочий сервер ARN не затрагивался. Доступы, ключи,
приглашения и клиентские профили в репозиторий не добавлялись.

## Проверено

- Базовая панель установлена на Rocky из локального образа, прошла healthcheck;
  сценарий включения Основного узла связал с ней отдельную службу и приватный
  сокет приглашений. Стабильный автоапдейтер не включился для тестового образа.
- Одноразовое приглашение доставлено Ячейке без вывода в терминал. Ячейка
  зарегистрировалась, установила постоянный AWG-канал и пользовательский
  интерфейс, получила и подтвердила подписанную ревизию №1.
- При перезагрузке Основного узла работающая Ячейка сохранила свой
  пользовательский интерфейс и ревизию. После возврата Основной узел восстановил
  обе службы и статус Ячейки. После отдельной перезагрузки ALT Ячейка сама
  восстановила контрольный и пользовательский AWG-интерфейсы. Ревизия №2,
  опубликованная после обоих reboot, автоматически применена и подтверждена.
- Одноразовые копии приглашения после регистрации удалены с обеих VPS.

## Исправлено по результатам прогона

1. Rocky/RHEL применяет `/usr/lib/sysctl.d/50-redhat.conf` с
   `net.ipv4.conf.*.rp_filter = 1` к каждому вновь созданному TUN-интерфейсу.
   Контейнер не может исправить `/proc/sys`, поскольку Docker монтирует его
   read-only. Установщики Основного узла и Ячейки теперь заранее создают
   отдельные root-owned файлы в `/etc/sysctl.d/` только для принадлежащих
   проекту интерфейсов со значением `2`; глобальные `all` и `default`
   не меняются. При reboot на Rocky оба интерфейса унаследовали `2`.
2. После прерванного запуска пользовательский процесс временного AWG-интерфейса
   исчезает, но его lifecycle-журнал остаётся `ready`. Очистка временного пути
   раньше восстанавливала маршрут до восстановления интерфейса и зацикливала
   перезапуск Ячейки. Теперь сначала под защитным guard восстанавливается
   принадлежащий интерфейс, затем его маршруты проверяются и удаляются.
   Добавлен регрессионный тест на этот порядок.
3. Для установки тестового локального образа инсталлятор теперь не делает
   попытку скачать его из реестра и не включает стабильный автоапдейтер;
   обычная установка опубликованного образа не меняется.

## Границы проверки

Проверена продуктовая установка и служебная связь, но **не** пользовательское
подключение к Ячейке: назначение входа/выхода профиля, Home/Guest,
IPv4/IPv6/GeoIP на двух VPS, DHT-резерв, согласованное обновление образов и
backup/restore ещё не готовы к релизной оценке. Чистый повторный прогон на
новых VPS потребуется после внедрения этих частей. Локально после исправлений:
`pnpm -C src test` — 704 теста, 664 пройдено, 40 платформенных пропусков,
ошибок нет; `pnpm -C src check` и `sh -n` сценариев установки успешны.

# Служебное управление Ячейкой внутри AWG: локальная точка, 2026-10-05

Закрыта часть перехода с TLS-регистрации на AWG-приглашение. Служебный
TCP-канал внутри AWG принимает подписанные запросы только от Ячейки с
завершённой регистрацией v2: запись `consumed/closed`, постоянные AWG-ключи
зафиксированы. Запись на стадии `ready`, даже после обмена ключами, доступа
не даёт. Смешивать старый TLS-store и новый AWG-store запрещено.

Перед открытием listener теперь проверяется private bind-адрес, его точное
соответствие адресу нашего `ready` AWG lifecycle-журнала, принадлежность и
целостность интерфейса через readback `verify()`, а также состояние UP.
Один лишь RFC1918/ULA-адрес не является доказательством принадлежности.
Клиентский sync v2 не может молча перейти на TLS; старый v1 требует TLS.

Локальные проверки: полный `pnpm test` после проверки listener — 503 теста,
473 passed, 30 platform-skipped, 0 failed. После последнего ограничения
версии/транспорта целевые `CellTunnelControlTransport` и
`ControlCertificateStore` — 11 passed, 0 failed. Полный набор следует
повторить после следующих изменений. Реальный AWG/VPS-тест этой новой связки
ещё не проводился.

Это не продуктовая готовность Ячеек: lifecycle, boot-обвязка, установка,
топология, отзыв, маршрутизация и интерфейс пока не сведены в один
развёртываемый контур. Рабочий ARN не использовался и не менялся.

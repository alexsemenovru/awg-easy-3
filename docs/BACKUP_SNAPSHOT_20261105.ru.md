# Снимок конфигурации для backup/restore — 5 ноября 2026

Добавлен `BackupSnapshot` поверх ранее проверенного AES-256-GCM конверта.
Это **компонент разработки**, не готовая кнопка backup/restore и не полномочие
на перенос управления Ячейками. В публичный CLI/установщик он пока не подключён.

Что уже проверено:

- Отдельный случайный ключ каждого архива; чужой ключ, изменение шифротекста,
  неверные хеши, неоднозначный JSON и неизвестный формат отвергаются.
- Только явный список известных файлов настроек панели/Основного узла;
  никаких tar-path, абсолютных путей, `..`, журналов ядра, логов трафика или
  адресной таблицы DHT. Список и общий размер ограничены.
- Проверяются приватность каталогов, владелец/права файлов на Linux,
  отсутствие symlink/hardlink и изменение источника во время чтения.
  Повторный проход сверяет хеши. `withQuiesced` обязан удерживать всех писателей
  остановленными/заблокированными: два чтения не заменяют согласованный снимок.
- Распаковка только в **новый** приватный каталог проверки с fsync и завершающим
  manifest. Существующий каталог не перезаписывается; файлы ничего не запускают
  и в действующую установку не продвигаются.
- Подготовка восстановленного состояния сохраняет серверные/клиентские ключи,
  профиль AWG, действующий TOTP и внутренний ULA-префикс. Привязки WAN,
  интерфейса, внешнего endpoint и портов берутся из явно проверенной целевой
  машины. Секрет сессий заменяется, незавершённая настройка TOTP отбрасывается.
  Ручной ввод прежнего IPv6-префикса не добавляется.
- Windows и Linux: семь проверок конверта/снимка; тесты читают и снова открывают
  настоящий зашифрованный архив и приватные файлы, без действующих профилей.

До продуктовой интеграции нужны автоматический полный инвентарь и семантическая
сверка всех связанных Main/Cell-файлов, координация остановки/блокировок,
надёжное сохранение архива с отдельным ключом, предыдущий снимок перед restore,
проверка целевого хоста и транзакционное включение новой установки.

Перенос управления Ячейками требует отдельного поколения полномочий,
подтверждений и защиты от старого/повторного takeover. Он не реализуется
простым копированием JSON или владением ключом расшифрования. Старые backup
нельзя автоматически объявлять отозванными у недоступной Ячейки без её
подтверждения; состояние подтверждений должно быть видно владельцу.

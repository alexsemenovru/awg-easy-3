# Проверка конфигурации и владения AWG

`CellAwgSnapshot` нормализует только stripped-конфигурацию `awg setconf/showconf`:
ключи, параметры AWG, peer/AllowedIPs, keepalive и literal endpoint. Хуки
wg-quick, маршруты, DNS и неизвестные поля отклоняются. В диагностические
ошибки содержимое конфигурации/ключи не подставляются.

Порядок peers, запись IPv6, диапазон `5-5` против `5`, пустой PSK и отсутствующий
keepalive учитываются семантически. Если endpoint клиенту не задавали,
обученный адрес после handshake не считается изменением конфигурации. Явно
заданный endpoint межсерверного peer проверяется точно после нормализации.
DNS-имена и scoped IPv6 endpoints пока не поддерживаются этим проверяющим кодом.
Нужен фиксированный listen port серверного интерфейса, не автоматически
выбранный порт клиентского интерфейса.

`CellAwgOwnership` требует приватный манифест с именем, случайным UUID-tag,
MTU и конфигурацией. Проверяется `ip -d -j link`: точный alias/tag, допустимый
тип интерфейса (TUN, amneziawg/wireguard), MTU и совпадение конфигурации.
Отсутствие интерфейса отличается от неподтверждённого владения и от изменения
своего интерфейса. Состояние UP возвращается отдельно: down не делает его чужим.

Ни один из этих компонентов **не присваивает, не перемаркировывает и не удаляет**
существующие интерфейсы. Манифест содержит секреты и требует хранения 0600.
Производственный жизненный цикл создания/изменения/удаления ещё не реализован.
Сбой между созданием и установкой tag не даёт права присвоить интерфейс по имени.
Одного tag недостаточно как защиты от администратора root; это проверка
владения для недопущения случайного изменения другой инфраструктуры.

## Проверки

- 5 unit tests снимка конфигурации, 4 unit tests владения.
- Настоящий AWG 3.1 showconf: исходная конфигурация совпала, изменённый Jc
  обнаружен, восстановленный config совпал. Проверены PSK, выключенные
  boolean-флаги, диапазон keepalive, IPv6 endpoint и alias/MTU/up/down.
- В routing lab оба клиента теперь используют настоящие AWG-туннели, а не
  имитацию расшифрованного трафика через veth. Межсерверный туннель также AWG.
  Все серверные AWG-интерфейсы проверяются по приватным манифестам, сохранённым
  до их создания. Проверены клиентские endpoints, обученные после handshake.
- При изменении протокольной конфигурации координатор не снимает уже активный
  guard; после явного восстановления исходного config проверка проходит.

Это не тест загрузки ОС и не завершённый продуктовый AWG runtime. Адреса
интерфейсов и sysctl пока подготавливает стенд, не новый lifecycle-компонент.

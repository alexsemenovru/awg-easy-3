## Реализовано

- Новые Основные узлы получают `fd08:8::1/64`. Существующие установки и
  restore сохраняют прежний ULA. Адреса Ячеек не уравниваются с Основным узлом.
- Выбор выхода профиля сохраняется в `exitNodeId`, доступен в API и карточке
  на пяти языках. Между Ячейками явно задан фиксированный путь через Основной
  узел; потеря пути не выбирает другой выход. IPv4-only выход выключает IPv6;
  повторное включение через API отклоняется. Это общий выход, **переадресация
  отдельных стран GeoIP ещё не реализована**.
- Подписанные команды обслуживания, привязка к Ячейке/живой authority,
  устойчивые журналы, отчёт о фактически запущенной версии. Удаление идемпотентно
  ставится в очередь, профили предварительно отключает единственный писатель —
  панель. Основной узел читает её состояние, не пишет в read-only `/data`.
- Кнопка удаления с одним подтверждением, числом отключаемых профилей и честным
  указанием, что число активных подключений неизвестно. Очередь не выдаётся за
  завершённое удаление. Защита текущего подключения/последнего Home сохраняется.
- Root supervisor вне контейнера (`cell-maintenance.sh`, systemd/OpenRC),
  пиннинг собственного Docker ID/образа, отсутствие Docker socket в Ячейке,
  остановка restart-policy, удаление только своих сетевых ресурсов/контейнера.
  Терминальный маркер препятствует повторному запуску удаляемой установки.
- Финальная квитанция подписана Ячейкой и отправляется после реального удаления
  контейнера. Отдельный узкий purpose служебного транспорта не передаёт VPN
  трафик. Ответ Основного узла подписан его исторической идентичностью, чтобы
  повтор терминальной квитанции переживал restore; это не команда управления
  и не ослабление authority для settings/routing/регистрации.
- Основной узел отзывает control peer, убирает свой data link, перестраивает
  маршрутизацию под guard, хранит tombstone и подтверждает завершение. Повтор
  квитанции безопасен. Retired receipt peers отделены от активного DHT-инвентаря.
- Backup учитывает подписанные журналы обслуживания; незавершённое удаление
  блокирует создание нового архива. После удаления последней Ячейки архив не
  включает исторический permanent base/revision, чтобы не воскресить её peer.
- Host supervisor содержит forward-only замену Ячейки официальным последним
  стабильным образом с Cosign-проверкой, но **реальная замена контейнера при
  обновлении ещё не испытана**. Общая интеграция обновления Main остаётся ниже.

## Всё ещё блокирует готовность релиза

1. Полное координированное обновление Main + panel + Cells. Запрет Main в
   `lib/auto-update.sh` намеренно остаётся; не снимать без целого сценария
   замены, проверки новой версии, сбоя/прерывания и безопасного восстановления.
2. Единый host restore с двумя **живыми** Ячейками, затем полная продуктовая
   матрица входов/выходов/Home/GeoIP/dual stack и отсутствия fallback.
   Раздельные удачные тесты не заменяют этот сценарий.
3. Переадресация выбранных стран GeoIP на другой выход, вместо только блокировки
   и общего выхода профиля; действующий UI/состояние этого ещё не предоставляют.
4. Новое требование владельца текущего релиза: раздельные входящий endpoint и
   исходящий IPv4/SNAT на многоадресном VPS. Обсуждено и внесено в BACKLOG,
   **не реализовано**. Само разделение адресов не гарантирует необнаружимость VPN.

Остались также проверка реального обновления Ячейки, свежих pending-команд при
restore, пользовательского удаления через сеть и изолированной автономной работы
после этих действий. Не объявлять пункты закрытыми по одним unit-тестам.

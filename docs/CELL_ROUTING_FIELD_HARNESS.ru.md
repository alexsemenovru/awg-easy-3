# Полевой harness согласованной маршрутизации

`scripts/cell-routing-field.cjs` — внутренний стенд для **пустых тестовых VPS**,
не публичная команда, не инсталлятор и не замена существующей панели.
Старые уничтоженные VPS/профили использовать нельзя.

Вызов под Linux:

```sh
AWG_CELL_FIELD_TEST=1 node scripts/cell-routing-field.cjs apply /private/runtime /private/bundle.json
AWG_CELL_FIELD_TEST=1 node scripts/cell-routing-field.cjs status /private/runtime /private/bundle.json
AWG_CELL_FIELD_TEST=1 node scripts/cell-routing-field.cjs recover /private/runtime /private/bundle.json
```

Пути абсолютные; каталог 0700, bundle 0600, владелец — запускающий пользователь.
Ссылки и публичные права отвергаются. Bundle имеет поля version=1, nodeId,
topology, context, geoDatabase, owners. Он содержит приватные AWG-манифесты,
может содержать PSK и **не должен попадать в Git/логи/сообщения**.

Все управляемые интерфейсы должны уже существовать, быть настроены самим
тестовым развёртыванием и иметь свои манифесты/tag. Присвоение старого интерфейса
по совпавшему имени не допускается. WAN, адреса, sysctl и AWG-процессы стенд
подготавливает отдельно. Здесь не реализованы reboot/bootstrap или удаление ПО.

Вариант **version=2** заменяет `owners` на `devices`: массив спецификаций
CellAwgLifecycle `{version:1, owner, addresses}`. Пустой список адресов допустим
для ненумерованного межсерверного туннеля. Такой bundle создаёт отсутствующие
интерфейсы сам и восстанавливает их по приватным журналам перед routing recover.
Полный набор устройств защищён guard до первого создания. Отпечаток набора
фиксируется в devices.sha256 до изменений ядра; любые изменения ключей, адресов
и состава устройств этим harness запрещены. Это запуск фиксированного набора,
не общий координатор динамической топологии. Частичный файл отпечатка после
сбоя отвергается, а не заменяется без проверки.

В v2 lifecycle выставляет rp_filter=2 только на собственных подтверждённых
интерфейсах: это нужно для удалённого выхода при строгом reverse-path режиме
хоста. Глобальные/WAN sysctl, forwarding, внешний firewall и underlay остаются
за тестовым развёртыванием. Пользовательский reboot/service hook не установлен.
`status` не создаёт интерфейсы и не восстанавливает журналы устройств.

Процесс запускается через системный `flock -n`, второй владелец того же
runtime-каталога отклоняется. Файл runtime.lock не удаляется: важен его inode,
а блокировка снимается ядром при завершении владельцев дескриптора. Для команд
требуется доступная утилита flock; нового фонового демона нет. Внутренний
аргумент `--locked-child` вручную не используют — это не граница защиты от root.
Обход harness при прямом вызове библиотек не получает эту межпроцессную защиту.

`recover` намеренно оставляет guard. Возобновление трафика — последующий явный
`apply` после проверок. `status.verified` означает совпадение маршрутов/policy и
интерфейсов, не отсутствие guard; наличие последнего показывает guardPresent.
Вывод не содержит bundle, ключей или сырого Error/stderr от AWG.

## Следующая полевая проверка

Два новых VPS с IPv4/IPv6: подготовить свежую тестовую топологию и манифесты,
проверить apply/status/recover, потерю туннеля, согласованный откат и отказ
конкурирующего процесса; не трогать посторонние интерфейсы/правила.
Отдельно проверять совместимость версий nft JSON и ядра, поскольку локальный
стенд использует один заранее известный образ. Не выдавать этот этап за
завершение GUI, установщика, signed topology delivery или DHT.

Особенности Astra Linux остаются обязательным пунктом будущего инсталлятора
и всех README: переносимый лабораторный набор не равен штатной поддержке ОС.

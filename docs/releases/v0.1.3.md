# AWG-Easy 3 — 0.1.3

Стабильный выпуск: отдельные разрешения IPv4/IPv6 для каждого клиента,
«Настройки доступа» и исправления установки на минимальном Alpine/OpenRC.

## Что изменилось

- Вместо общего переключателя «Клиент включён» — независимые IPv4 и IPv6.
  Обе семьи выключены — клиент отключён, peer удалён из работающего AWG.
  Home/Guest остаётся независимой настройкой.
- Переключатели находятся в сворачиваемых **«Настройках доступа»**. Режим
  трафика виден и при закрытом разделе; «Диагностика» остаётся только для чтения.
  Обновление карточек сохраняет открытые разделы и фокус переключателя.
- Запрет действует в обе стороны внутри VPN, в том числе для уже открытых
  соединений, Home ↔ Home и служб сервера. Чужие интерфейсы, контейнеры и
  правила VPS не меняются. Ключи, адреса, DNS, маршруты и экспортируемый профиль
  при переключении не перевыпускаются; повторный импорт не нужен.
- Панель доступна по внутреннему IPv4 и, при наличии, собственному IPv6.
  Ссылки доступны в разделе «Разрешения трафика VPN». Защита не даёт отключить
  текущий путь администрирования или последнего разрешённого Home-клиента.
- Существующие клиенты 0.1.2 получают разрешения доступных семейств без
  перевыпуска ключей. Ранее отключённые клиенты остаются отключёнными.
- На минимальном Alpine исправлены применение собственного sysctl-файла
  через BusyBox, создание `/usr/local/sbin` и сохранение загрузки TUN после
  reboot. Одноразовая задача OpenRC больше не оставляет ложный статус `crashed`.
- Новые настройки, предупреждения и ошибки переведены на все пять языков.

## Обновление

```bash
sudo awg-easy-3 update
sudo awg-easy-3 status
```

Обычное обновление сохраняет клиентов, ключи, пароль, порт и настройки.
**Не используйте `reinstall` для обновления:** он намеренно удаляет конфигурацию.
Управляемый Git-клон должен быть без собственных изменений отслеживаемых файлов.
Во время замены контейнера возможен краткий перерыв VPN. После обновления
перезагрузите страницу панели, чтобы получить новые элементы интерфейса.

Образ выпуска: `ghcr.io/alexsemenovru/awg-easy-3:0.1.3` (`linux/amd64`).
Публикация описания выпуска выполняется только после успешной сборки и отправки
образа. Стабильный тег контейнера `latest` указывает на этот выпуск.

## Важные ограничения

- **IPv6-only не гарантирует работающий DNS.** AmneziaVPN может применять
  только свои IPv4-поля DNS, даже если профиль содержит IPv6 DNS. В ручном тесте
  прямой IPv6 работал при запрещённом IPv4, но доменные имена не разрешались;
  включение IPv4 восстановило их работу. Фактически выбранные приложением DNS
  и все сочетания ОС/способа импорта отдельно не подтверждены.
- Исключений для IPv4 DNS, NAT64, WARP и автоматического direct fallback нет.
  IPv4-only сайты в IPv6-only недоступны. Панель управляет только трафиком
  внутри туннеля, а не раздельной маршрутизацией и kill switch на устройстве.
  Для базовых проверок отключите клиентский фильтр «только выбранные сайты».
- Discovery relay использует IPv4: запрет IPv4 исключает клиента из mDNS/SSDP
  ретрансляции. Это не реализация discovery по IPv6. Видимость сервисов также
  зависит от поддержки VPN-интерфейса клиентским приложением.
- После полного отключения и возврата клиента может потребоваться новый
  handshake. Мгновенное восстановление при любых состояниях сети не обещается.
- **Ручной downgrade не бесшовный:** старые версии не знают новых флагов.
  Совместимое поле состояния намеренно отключает частично ограниченного клиента
  для старого кода, чтобы тот не открыл запрещённую семью. При отсутствии
  совместимого Home-профиля старая версия может отказаться запускаться.

## Что проверено

- 203 локальных автоматических теста без ошибок и пропусков.
- Полный производственный Dockerfile собран на Alpine 3.23.5/OpenRC.
- Миграция с runtime 0.1.2 с сохранением ключей, профилей и отключённых клиентов.
- 134 проверки настоящих AWG-туннелей и 82 дополнительные пакетные проверки
  в изолированной сети: четыре режима, оба направления, DNS, изоляция и
  существующие соединения. Защита последнего IPv6-only Home проверена отдельно.
- Рестарт контейнера и реальные перезагрузки ОС: разрешения сохранены, VPN
  стартует, отложенная проверка OpenRC выполняется один раз. Соседний сервис
  и сторонняя инфраструктура сохранены; удаление и повторная установка проверены.
- Пользователь подтвердил цикл блокировки/восстановления IPv6, прямой IPv6 при
  запрещённом IPv4 и восстановление DNS после разрешения IPv4.
- Финальный перенос переключателей в «Настройки доступа» проверен локально
  в браузере, включая пять языков, мобильную вёрстку и RTL. К этому моменту
  тестовый VPS был удалён; эта UI-правка не выдаётся за дополнительный полевой тест.

## English summary

Stable 0.1.3 adds independent per-client IPv4/IPv6 permissions in collapsible
Access settings. Both off disables the peer; Home/Guest remains independent.
Permissions cover both directions inside the VPN without regenerating profiles.
The panel also binds its internal IPv6 address and protects the current access
path and last permitted Home client. Existing 0.1.2 clients and keys are retained.

Minimal Alpine installation and OpenRC boot handling are fixed and field-tested.
Coverage includes 203 local tests, real AWG packet tests, migration and OS reboots.
Final UI changes were browser-tested locally after the disposable VPS was deleted.
IPv6-only may lose DNS resolution depending on AmneziaVPN's applied DNS settings;
no DNS bypass, NAT64, WARP or direct fallback is added. Manual downgrade can fully
disable partially restricted clients. Update with `sudo awg-easy-3 update`, not
`reinstall`.

# Межсерверная маршрутизация: локальный этап 2026-09-16

Это внутренний прототип, не возможность текущего релиза. Старые тестовые VPS
уничтожены; к ним не подключаться. Новых VPS для этого этапа не использовали.

## Реализовано

`CellTopology` проверяет топологию с одним Основным узлом, Ячейками и прямыми
связями. Клиент имеет отдельные назначения entry/exit. Состояние доступности
серверов не влияет на выбор пути: планировщик не переназначает выход при отказе.
Нет прямой связи или нужного семейства на назначенном пути — разрешение этого
семейства закрыто с машинной причиной для будущей подсказки UI.

Ключи/PSK клиента входят только в план сервера входа. Маршрутный план других
серверов содержит адреса, Home/Guest, GeoIP-политику и разрешения, но не ключи.
Техническая граница нового валидатора — 128 серверов и 1000 клиентов; это лимит
прототипа, **не подтверждённая вместимость продукта** и не прежний предел записей
приглашений. Производительность больших топологий пока не измерялась.

`CellRoutingPolicy` компилирует отдельную таблицу `inet awg_easy_3_routes` и
массивы argv для маршрутов/rules. Сам ничего не применяет. Основная панель,
CellSettings schema=1 и прежний CellRuntimeAdapter остаются без изменений.

- Отдельный AWG-интерфейс на каждую прямую межсерверную связь. Это позволяет
  использовать широкие AllowedIPs для ответов из интернета без конкуренции
  нескольких default-peer в одном интерфейсе.
- AllowedIPs не устанавливаются как default маршруты ОС: маршруты управляются
  отдельно. Селекторы policy routing ограничены iif клиентского интерфейса и
  точным исходным адресом клиента. Трафик самого VPS не перенаправляется.
- У каждого удалённого выхода отдельная таблица с маршрутом через туннель и
  терминальным unreachable default. При удалении интерфейса lookup не должен
  проваливаться в обычный WAN. Независимая nft-проверка выходного интерфейса
  блокирует обход, даже если policy rule исчезнет.
- NAT только на выбранном выходе; на межсерверной связи исходный клиентский
  адрес сохраняется. Обратные host-маршруты привязаны к серверу входа.
- Home между входами разрешён явно; Guest и отключённые семьи изолированы.
  Для Home предусмотрен доступ к точному адресу/порту панели Основного узла.
- GeoIP проверяется до разрешения интернет-трафика и на обратном направлении,
  на входном и выходном сервере. Нет требуемой страны в базе — ошибка компиляции,
  а не снятие фильтра. Home-связность, как и раньше, не фильтруется по GeoIP.

## Что доказано тестами

Общий набор: 312 тестов, 309 прошли, 0 ошибок, 3 платформенных пропуска.

Изолированная WSL rootfs с mount/net/PID namespaces, без изменения основной
сети WSL. Два виртуальных сервера соединены **настоящим userspace AWG**.
Телефон/настольный клиент имитируют уже расшифрованный трафик через veth;
это не повтор проверки импорта в AmneziaVPN на реальном телефоне.

Пройдены:

1. Синтаксис nftables и установка реальных policy rules/маршрутов.
2. Вход через Ячейку, выход через Основной узел по IPv4 и IPv6.
3. Home-связность клиентов разных входов и доступ Home к HTTP-стенду панели.
4. Отказ Guest в доступе к Home и панели при сохранении интернета.
5. Независимые запреты IPv4/IPv6 и GeoIP-block на синтетической базе.
6. Удаление межсерверного туннеля: блокировка, без запасного выхода.
7. Дополнительное удаление policy rule: nft всё равно предотвращает утечку.
   Обычный WAN самого виртуального VPS при этом остаётся доступен.
8. Повтор прежнего теста CellRuntimeAdapter: реальный AWG, семейства/GeoIP,
   откат syncconf, guard и сохранность посторонней nft-таблицы — успешно.

Проверен вариант со strict rp_filter=1 глобально внутри виртуальных серверов и
loose rp_filter=2 только на своих клиентских/межсерверных интерфейсах. Нельзя
без необходимости отключать rp_filter глобально на пользовательском VPS.

Яндекс Браузер: бинарник и профиль не изменялись; команда версии возвращает
26.8.1.1022, SHA256 `04f00b075735780f2011b99f4e503a2ae6c87b1fc2ae3d0d81250202db78e1f7`.
GUI не запускался. Основная nft-таблица WSL пуста; тестовые правила были только
в отдельных namespaces. Сетевая конфигурация основной WSL не переписывалась.

## Следующий полевой этап и границы

Нужны две **новые** VPS для проверки MTU, реальных обратных маршрутов, IPv6,
потери связи и Home между серверами. Это испытания маршрутизирующего прототипа,
а не готовых кнопок выбора входа/выхода в панели.

Перед продуктовым подключением ещё нужны:

- ownership-aware транзакционный применитель нескольких интерфейсов, маршрутов
  и правил с guard, откатом и восстановлением после сбоя; конфликты номеров таблиц,
  приоритетов и адресов нельзя решать перезаписью чужих объектов;
- подпись/доставка нового формата топологии, распределение только публичных
  параметров межсерверных туннелей и учёт несовпадающих ревизий на сторонах;
- общий план применять только после проверки контекста/маршрутов целиком;
  текущие argv — описание, не разрешение запускать их поверх рабочей установки;
- подключение к установщику/службе/GUI, смена выхода действующего клиента,
  дополнительные правила выбора выхода по GeoIP (здесь пока только default exit
  и GeoIP-запреты), несколько Ячеек, удаление/отзыв и резервная сеть управления.

Не обещать бесшовную смену выхода или готовую mesh/DHT. Не переключать выпуск
с текущего локального runtime на этот компилятор без следующих проверок.

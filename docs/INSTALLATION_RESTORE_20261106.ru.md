# Продуктовая команда восстановления — 6 ноября 2026

Рабочая ветка, без публикации релиза. Восстановление выполняется на новой
инициализированной standalone-установке с текущим образом этой ветки:

```sh
sudo awg-easy-3 restore /absolute/configuration.awgbackup /absolute/recovery-key.txt
sudo awg-easy-3 restore --resume
sudo awg-easy-3 restore --rollback
```

Архив и ключ должны быть разными приватными обычными файлами. Значение ключа
не передаётся аргументом и не выводится в журнал. Существующая сеть Ячеек на
машине назначения не заменяется: команда её обнаруживает и отказывается.
Это перенос на новый хост, не слияние двух сетей.

До остановки рабочей панели архив расшифровывается и проверяется. Подготовка
сохраняет профили, ULA и TOTP, заменяет browser cookies и live authority,
использует адресные настройки новой машины. Статические метаданные отделены
от журналов владения ядром; последние не копируются с прежнего VPS.

После штатной остановки проверяется освобождение требуемых интерфейсов,
портов и nft-таблиц. Исходный каталог `data` целиком сохраняется под приватным
`.restore/<transaction-id>/previous/data`. Он не публикуется как новое поколение
backup и не аннулирует переданный пользователем архив. Новый `data`, состояние
Main и его host bindings устанавливаются проверяемыми переименованиями в одной
файловой системе. Журнал намерений, inode-проверки, fsync и сверка хешей позволяют
продолжить процесс после разрыва между rename и записью результата.

До запуска восстановленных служб доступен обратный проход `--rollback`.
Перед запуском записывается долговечная граница `starting`: после неё Ячейка
может закрепить новую authority, поэтому файловый откат запрещён. При ошибке
запуска данные сохраняются; `--resume` повторяет запуск новой установки.
Обычные start/restart/update и разрушительные команды менеджера блокируются
при незавершённой транзакции. Общая installation/update lock не перехватывается;
после SIGKILL оставшаяся в `/run` блокировка очищается перезагрузкой ОС.

Проверка здоровья теперь использует сохранённые интерфейс, порт и внутренний
IPv4 панели, а не захардкоженные `awg0`/`10.8.0.1` или старый environment.
Пользователям с прямым входом через прежний публичный IP может понадобиться
замена endpoint в клиенте; сохранение ключей само по себе IP не перенаправляет.

## Подтверждение и границы

На Ubuntu 26.04 выполнена настоящая `restore.sh` с Docker Compose:
зашифрованный Main-архив с двумя регистрациями, независимая исходная панель,
замена ключей исходной панели на архивные, новый endpoint/порт/interface,
сохранённый предыдущий каталог, здоровая панель и запущенный Main. Дополнительно
проверены сбой после rename до журнала, продолжение и допустимый откат,
изменение целевой конфигурации и занятые ресурсы.

В этом стенде две регистрации не изображают две работающие удалённые Ячейки:
сквозной takeover реально подключённых Ячеек требует отдельной проверки.
Образ стенда собран из актуальных исходников поверх прежнего lab runtime;
сборку настоящего Dockerfile подтверждать отдельно через CI.

CI `cc3aace5` успешно выполнил реальную host-команду с образом из настоящего

## Дополнение: обнаружение и внешний IPv6

Восстановленный Main дополнительно публикует короткие DHT locators под ключами
recovery и live authority. Ячейка ищет только по ключам из уже принятого grant
и закреплённой authority; после её смены исторический controller key не нужен
как единственный locator. Запись содержит только адрес связи и срок жизни.
Конфликт публикации исторического ключа не подавляет публикацию новых aliases.
Технический протокол v2 передаёт посреднику подписанный locator key, сохраняя
исходную проверку конечного Main и зарегистрированного происхождения запроса;
технический v1 также читается. Три настоящих UDP-участника подтвердили alias-
обнаружение и повторную публикацию при отказе исторического locator. Передача
через один посредник с отдельным locator и прежним конечным peer key проверена.

Recovery-материал содержится в архиве: владелец архива вместе с ключом способен
им пользоваться. Это не обещание защиты от злонамеренного владельца прежнего
хоста, сохранившего обе части. Live authority после принятия proof независима
от исторического ключа; старые ответы управления Ячейка отвергает.

Перенос назначения теперь работает и для внешнего IPv6: точные ip6 output-DNAT
и IPv6 conntrack tuples, проверка владения, прежние пинованные AWG-конфиги и
guard перед изменением. Настоящие control/data AWG в разных namespace прошли
перенос при недоступном старом IPv6; повторный проход ничего не изменяет.
Смена внешней семьи IPv4↔IPv6 таким DNAT не поддерживается и отклоняется с
сохранением guard. Это не NAT64; при DNS адрес фиксируется отдельно для каждой
ранее выбранной внешней семьи. Внутренний dual stack от неё не зависит.

Дополнительный реальный IPv4-сценарий получает takeover **через recovery RPC**:
старый UDP-адрес недоступен, исходный AWG control проходит через технический
мост, Ячейка проверяет свежий challenge/grant, закрепляет новую authority и
получает новый адрес из проверенного proof. Затем создаётся точный DNAT для
control/data, технический мост отключается и оба AWG-пути работают напрямую.
Ячейке в этом сценарии не передаются приватные ключи recovery/Main.
Подтверждение поколения получает настоящий MainBackupStore.

Граница проверки: адрес технического моста дан стендом, не получен из публичной
DHT; полное восстановление работающей сети через host-команду всё ещё нужно
проверить отдельно. Внешний IPv6-тест проверяет перенос транспорта с уже
принятым proof: технический резерв пока рассчитан на внешний IPv4.

При импорте сбрасываются архивные settings-ack/confirmed и routing-ack:
они не подтверждают получение настроек от восстановленного Main. Desired
настройки/маршруты сохраняются. Управляющие запросы v2 подписывают текущий
authority key; восстановленный Main отвергает запросы к прежней authority,
включая ещё свежие записи ack из старой сессии. Отдельный recovery-запрос
сохраняет исходный формат для первого доказательства takeover. Обычный Main
без восстановленной authority продолжает принимать v1. Пользовательские
AWG-профили и ключи при этом не меняются.

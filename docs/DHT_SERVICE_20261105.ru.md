# Служба обнаружения DHT — 5 ноября 2026

В `serve` Основного узла и Ячейки подключён отдельный worker на закреплённом
`bittorrent-dht 11.0.12`. Торренты и содержимое пользовательских соединений
он не загружает. Это рабочее обнаружение, **ещё не резервная доставка
управления/телеметрии и не готовность объединённого релиза**.

## Что реализовано

- Вход через три стандартных адреса публичной BitTorrent DHT и сохранённые
  контакты. Диск хранит до 128 контактов в приватном каталоге; значения чужих
  BEP44-записей не сохраняются. Пустая таблица после разрыва не стирает
  прежние точки входа.
- Подписанные Ed25519 указатели с временем жизни 15 минут и раздельными
  ролями `main`/`cell`. Поиск ведётся только по идентичностям зарегистрированных
  соседей; последовательности сохраняются и не откатываются после перезапуска.
  Порт указателя — порт обнаружения DHT, не порт веб-панели или VPN-клиентов.
- Автоматический выбор отдельного UDP-порта установщиками, сохранение его
  в установочной записи, исключение занятых сокетов, портов AWG и Docker DNAT;
  добавление порта в firewalld и инструкцию для firewall провайдера.
- Ограничение принятого/отправляемого UDP: 8 КиБ/с и 32 пакета/с в каждом
  направлении с кратким начальным запасом; максимальная датаграмма 2048 байт.
  Очередь отправки не создаётся. Разбор bencode и проверка подписи происходят
  после входного ограничения. Это ограничение обработки приложением, не
  гарантия от входящего сетевого flood на уровне провайдера/ядра.
- Отдельный worker с лимитами V8: old generation 32 МиБ, young generation
  8 МиБ, stack 2 МиБ. Это не предел полного RSS процесса. Таблицы и кэши
  библиотеки ограничены; одновременно работают два исходящих RPC.
- DHT-ошибка не останавливает AWG и не меняет маршруты. Worker перезапускается
  с задержкой; штатное завершение закрывает сокеты. Наружу передаются только
  агрегированные показатели, без адресов, ключей и пользовательских данных.
  Число контактов таблицы не выдаётся за общее число участников сети.

## Исправления, подтверждённые испытаниями

1. BitTorrent DHT сохраняет у себя immutable put, но не собственный mutable
   put. Если хранитель исчезал, живой владелец переставал отвечать о себе.
   Добавлен изолированный адаптер `BittorrentDhtOwnRecord` для версии 11.0.12:
   он проверяет подпись собственного указателя и помещает его в ограниченный
   локальный кэш библиотеки. Этот внутренний API требует повторного теста
   при обновлении зависимости.
2. Проверенные соседние адреса добавляются в таблицу и сохраняются как точки
   входа. После исчезновения начального хранителя они позволяют восстановить
   поиск. Первоначальный тайм-аут 3 с оказался короче обхода неработающих
   контактов библиотекой; используется 10 с.

## Проверено

- Windows: реальный UDP-обмен трёх экземпляров, подписи, роли, ограничения,
  сохранение контактов, исчезновение хранителя, повторный запуск и worker.
- Ubuntu 26.04.1 и CentOS Stream 10: нативные тесты нового компонента.
- Между **тремя разными ВМ**: Debian как начальный хранитель, Ubuntu как Main,
  CentOS как Cell. Обе стороны обнаружились. Затем хранитель остановлен,
  Cell запущена повторно с пустым списком bootstrap; Main найден по прежним
  контактам. Последний результат Cell: `located=true`, три успешных проверки,
  ошибок и отброшенных пакетов нет.
- Полный Linux-прогон в одноразовом контейнере Debian:
  **845 успешно, 0 ошибок, 0 пропусков**. Включены проверки nft в отдельных
  сетевых пространствах; concurrency=2 соответствует небольшому стенду.
  Журнал сохранён в игнорируемом `private-test-access`.

Публичная межрегиональная связность и полная установка нового образа
Узла/Ячейки этим раундом не подтверждены. Для испытаний применялись новые
случайные тестовые идентичности, а не ключи действующих клиентов.

## Продолжение

Нужны резервный технический транспорт поверх найденных контактов, статус
этого пути в панели, согласованное обновление, backup/restore и завершение
удаления. Само обнаружение не даёт права менять привязку/конфигурацию AWG.
Возможный путь дальнейшего прототипа: ретранслировать только отдельный
служебный AWG-контур, сохраняя его существующую криптографическую проверку;
пользовательский data-link через техническую сеть не направлять. Требуются
проверка владельца/адреса назначения, ограничения relay и журналируемое
переключение маршрута без ослабления readback-проверки AWG.

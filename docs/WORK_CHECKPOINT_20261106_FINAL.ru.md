# Контрольная точка: седьмой функциональный цикл

Учёт владельца: шесть функциональных циклов были использованы до начала этой
работы; текущий — седьмой и последний из согласованных семи. Предыдущий
исключённый владельцем цикл не добавляется обратно. Отдельный восьмой цикл
предназначен для дизайна/пяти README/разбора сообщения AmneziaVPN, а не для
незаметного переноса сюда незавершённых функциональных обязательств.
Публикация релиза — отдельно по согласованию. Ручных сбросов лимита не было.

## Сохранённые изменения

Ветка `codex/cells-foundation`, без release tag и публикации образов:

- `68f396eb`: настоящая host-команда `restore.sh` / `awg-easy-3 restore`:
  подготовка до остановки, сохранение предыдущего data, журналируемые rename,
  resume после прерывания, rollback до запуска новой authority, запрет отката
  после начала обслуживания Ячеек. Healthcheck читает сохранённую конфигурацию.
- `cc3aace5`: CI запускает реальную host-команду restore с образом, собранным
  настоящим Dockerfile, на одноразовом runner.
- `4bd58a96`: recovery/live-authority DHT aliases, подписанный выбор locator
  для одного технического посредника, перенос точного control/data UDP tuple
  на новый внешний IPv6 без изменения пинованных AWG-конфигураций.
- `c753fd54`: первый слой упаковки метаданных Ячейки, маркер на каждую версию,
  чтение старых файлов и миграция под flock, нейтральный `network-service`.
  Небольшие AWG-временные файлы — в приватном /run; большие nft-пакеты — через
  unlinked inode, без заполнения маленького tmpfs. Отмена control poll при stop;
  ротация отсутствующих DHT aliases между попытками, чтобы бюджет посредника
  не мешал добраться до актуальной authority.
- `d3842fcd`: подпись будущих образов через GitHub OIDC/Cosign; standalone
  updater проверяет identity/issuer/version/revision/digest до изменения
  установки, запускает проверенный digest. Верификатор — закреплённый
  официальный образ, временный контейнер без capabilities/socket/mounts,
  с лимитом памяти 192 MiB. Запрет panel-only обновления Main **сохранён**.
- `9e46e352`: при restore сбрасываются архивные settings/routing receipts;
  запросы control v2 подписывают новую authority, старые ack больше не могут
  выдаваться за подтверждение восстановленного Main. Реальный recovery RPC
  через резерв проверен отдельно; Cell-test запускает production link-agent
  вместе с миграцией старых файлов, а не обходит этот вход через CLI.

TOTP/режимы входа, фон Pride, уведомления/подсказки, транслитерация экспортов,
Home-группы, переименование профилей, выбор адреса и пять языков установщика
остаются в этой же ветке. Их не выносить из выпуска Узлов/Ячеек.

  `AWG_NFT_KERNEL_TEST=1`, concurrency=2. Пропуск относится к отдельному
  контейнерному restore kernel test; CI запускает его отдельным шагом.
- CentOS Stream 10: **23/23** для упаковки, control cancel, transport и runtime.
- Windows/Git Bash updater: **24/24**; реальный transport/backup-набор —
  **29 успешно, 1 opt-in пропуск** после исправления authority requests.
- Debian, реальные AWG/nft, Main + две Ячейки: регистрация, восстановление
  control, независимые настройки, отзыв клиента, GeoIP, сохранение чужих
  ресурсов. Включён `AWG_PRIVATE_STATE=1`; перезапуск Cell через link-agent
  также проверяет миграцию plaintext-файлов. Все проверки прошли.
- Важная граница этой старой фикстуры: она публикует settings без подписанной
  routing revision. Product-служба **обязана удержать guard**. Положительные
  NAT/GeoIP-проверки здесь выполняются standalone settings-adapter отдельно;
  их нельзя выдавать за сквозную продуктовую маршрутизацию.
- Реальный IPv4 recovery RPC: старый endpoint недоступен, прежний AWG control
  проходит через технический мост, Cell проверяет grant/challenge/proof,
  закрепляет authority, затем оба AWG-пути переходят напрямую на новый IP.
  Частные ключи Main/recovery в Cell-процесс не передаются. Повторный проход
  ничего не меняет. TLS не используется.
- Реальный внешний IPv6: перенос control/data с уже принятым proof, прежние
  пинованные endpoints, повторный проход без изменений. Это **не проверка
  технического IPv6-резерва**: он пока IPv4-only.
- Настоящий ограниченный контейнер Cosign проверил подпись своего официального
  образа и отверг старый неподписанный образ панели. Наш собственный новый
  образ до отдельно согласованной публикации не подписывался/не публиковался.
- Зелёный полный CI для `c753fd54`:
  [42180255951](https://github.com/alexsemenovru/awg-easy-3/actions/runs/42180255951).
  Он включает production Dockerfile, полный Linux suite, реальный reserve,
  IPv4/IPv6 migration, kernel restore, две Ячейки и настоящую host-команду.
  Итоговый запуск для `9e46e352` также прошёл полностью:
  [42183875980](https://github.com/alexsemenovru/awg-easy-3/actions/runs/42183875980).

## Что всё ещё препятствует релизу

1. **Координированное forward-only обновление Main/Cell не завершено.**
   Подписанный пакет/ежедневная проверка готовы, но это ещё не управление
   заменой контейнеров Ячеек, согласование версий и автоматический ack Main.
   Не снимать существующий запрет и не открывать Docker socket внутри Cell.
2. **Продуктовое удаление Ячейки не завершено.** Нужны аутентифицированная
   доставка команды, отзыв доступа, безопасное удаление только собственного
   контейнера/ресурсов, подтверждение результата, offline-состояние/очередь и
   предупреждение об активных пользователях. Чистый removal-plan и revision
   journal не заменяют эту функцию. Не показывать успешное удаление только
   потому, что пропал heartbeat.
3. **Не пройден единый сквозной restore через host-команду с двумя живыми
   удалёнными Ячейками.** Команда и recovery transport проверены по отдельности;
   не объединять эти свидетельства в вымышленный успешный общий сценарий.
4. Итоговая продуктовая матрица нескольких Ячеек/выбранных выходов/Home-групп,
   отсутствия fallback, GeoIP и dual stack после update/restore/удаления должна
   пройти с готовыми пунктами 1–2. Unit/namespace tests не подменяют её.

Эти обязательства не завершены в семи циклах. Не объявлять релиз готовым и
не расходовать дополнительный функциональный цикл без решения владельца.
Восьмой дизайн-цикл и публикация не изменяют эту оценку.

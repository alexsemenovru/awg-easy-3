# Полевой раунд Основного узла и Ячейки — 2026-10-22

Владелец предоставил две временные пустые VPS: первоначальную AMS (NixOS 25.11),
затем заменённую им AMS (Ubuntu 26.04.1), и MOW (Debian 13). Обе новые машины —
amd64, около 900 МиБ RAM/15 ГиБ диска. Адреса, SSH-реквизиты,
ключи и профили в отчёт не включаются. Рабочий ARN не используется.

## Начальная проверка

- SSH host keys обеих VPS сохранены при первом подключении; пароли читаются
  только из предоставленных файлов и не передаются в аргументах процессов.
- MOW доступен по SSH через AMS. При прямом соединении с рабочего компьютера
  периодически отсутствует SSH banner; TCP-порт 22 при этом открыт.
- На обеих VPS Docker и nftables отсутствовали, пользовательский AWG и проектные
  контейнеры не обнаружены. Порт 10050 занят агентом хостинга; проектные порты
  свободны. На AMS публичный IPv6-адрес автоматически не назначен.
- На AMS подготовлен штатный NixOS-модуль из инструкции `install.sh`.
  Исходный `/etc/nixos/configuration.nix` сохранён на той же VPS как
  `/etc/nixos/configuration.nix.pre-awg-20261022`; добавлен import отдельного
  `/etc/nixos/awg-easy-3-runtime.nix`. Синтаксис проверен. Запущено
  `nixos-rebuild switch --option max-jobs 1 --option cores 1`.

## Полевой результат на заменённой AMS

- NixOS rebuild на минимальной первоначальной AMS надолго загрузил CPU и
  лишил новые SSH-соединения banner. Владелец заменил эту VPS. Это ограничение
  данного полевого стенда, не доказанный общий дефект NixOS.
- На Ubuntu и Debian установлены Docker Compose v2 и nftables. Для сборки на
  Ubuntu с 889 МиБ RAM временно добавлен 2 ГиБ swap; один образ из коммита
  `cae4a0b8` успешно собран и загружен на MOW. Рабочий ARN не менялся.
- Основной узел установлен из локального образа; Ячейка зарегистрирована по
  одноразовому AWG-приглашению. Постоянный канал и подписанные ревизии №1–3
  подтверждены обеими сторонами. Копии приглашения удалены.
- Создан Guest-профиль с входом через Ячейку. В изолированном контейнере
  тестовый клиент установил AWG-handshake, получил ответы от внешнего адреса,
  а независимая проверка HTTP показала выход именно через Ячейку, не через
  Основной узел. Первое из трёх ICMP-сообщений потерялось при рукопожатии;
  дальнейшие ответы пришли.
- Создан Home-профиль через ту же Ячейку, ревизия №3 подтверждена, но доступ
  к панели Основного узла по внутреннему адресу завершился тайм-аутом.
  Диагностика маршрута на Ячейке показала, что адрес панели направляется в
  обычный публичный WAN, а не в постоянный межсерверный AWG-канал.
  `CellArtifacts` сейчас прямо ограничен локальным входом/выходом; чистый
  продуктовый сценарий Home через Ячейку **не реализован**. Это блокер релиза,
  несмотря на успешный статус регистрации и Guest-трафик.
- После полной перезагрузки MOW Docker сам запустил Ячейку, постоянный путь и
  ревизия №3 восстановились; прежний Guest-клиент снова вышел именно через
  Ячейку. Повторной регистрации не потребовалось.
- Контейнер Ячейки называется нейтрально `network-relay`; Node и пользовательский
  AWG-процесс идут как `link-agent.js` и `net-forward`. Но `docker top` всё ещё
  показывает `amneziawg-go awgcellc0` для служебного пути и узнаваемые имена
  интерфейсов. Первый слой маскировки **частичный**, это не защита от анализа.

Проверка reboot Основного узла, межсерверного выхода, IPv6, GeoIP, DHT, согласованных
обновлений и backup/restore в этом раунде пока не выполнена. Тестовые профили
и их ключи остаются только на временных VPS.

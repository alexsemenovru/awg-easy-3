# Сверка внешнего аудита безопасности — 2026-09-30

Источник: предоставленный владельцем текст «Аудит безопасности проекта awg-ea.txt».
Это оценка замечаний, а не инструкция к автоматическому изменению продукта.
Код или действующий FRA в рамках этой сверки не менялись.

## Принять в работу

- `POST /api/v1/session` сейчас не имеет отдельного ограничения частоты или
  числа параллельных проверок пароля (`HttpServer`, `ApiService`,
  `PasswordManager`). Панель слушает только внутренние VPN-адреса, поэтому
  доступна Home-клиентам, а не всему Интернету; это уменьшает поверхность, но
  не отменяет риск при утечке Home-профиля. Перед релизом полезен ограниченный
  по памяти token bucket по фактическому `request.socket.remoteAddress` плюс
  общий предел нагрузки. Не доверять `X-Forwarded-For`, не делать постоянную
  блокировку аккаунта, проверить IPv4/IPv6, перезапуск и реакцию UI на 429.
- Добавление `Permissions-Policy: geolocation=(), microphone=(), camera=()` —
  небольшое усиление браузерной политики. Оно не заменяет авторизацию,
  изоляцию панели внутри VPN или CSP. Достаточно включить в общий набор
  заголовков и покрыть тестом, когда будем делать соответствующий патч.

## Не применять предложенную правку напрямую

- Контейнер действительно запускается от root с `NET_ADMIN`, в host network,
  с `/dev/net/tun` и `/data`; `read_only` и `no-new-privileges` уже заданы.
  Простое `USER node` не является проверенной заменой: надо отдельно испытать
  полномочия `awg`/`nft`, доступ к `/data` и `/run`, запуск и восстановление
  сети на поддерживаемых ОС. Это направление hardening, не однострочный фикс.
- `Secure` для сессионной cookie не следует включать по умолчанию: штатная
  панель сознательно работает по HTTP *внутри* Home VPN. Опция есть в
  `SessionManager`/`ApiService`, но `HttpServer` сейчас её не передаёт.
  Автоматически доверять клиентскому `X-Forwarded-Proto` нельзя. HTTPS-прокси
  не входит в согласованную архитектуру; если поддержка появится, потребуется
  явная доверенная конфигурация прокси и отдельные тесты.
- GeoIP уже хранит SHA-256 локального снимка, проверяет gzip/CSV, пределы
  размера, охват IPv4/IPv6 и сохраняет прежнюю базу при отказе обновления.
  Это контроль повреждения локальных данных, не криптографическая
  аутентификация издателя. Хеш, полученный вместе с файлом из того же
  скомпрометированного источника, не устранит этот риск. Независимую подпись
  или доверенный второй канал можно исследовать отдельно, если источник их
  предоставляет.

## Уточнения к похвалам аудита

- `HttpOnly` не устраняет XSS и не является защитой от CSRF сам по себе;
  здесь также есть `SameSite=Strict`, CSP и проверка Origin/Sec-Fetch-Site.
- `buildAtomicNftBatch` запрещает произвольное `flush ruleset`/`delete table`
  *в тексте политики*, но при замене намеренно удаляет только собственную
  таблицу `awg_easy_3`. Откат имеет обработку ошибок, поэтому не следует
  обещать его безусловный успех при отказах ядра/диска.
- Dependabot уже предлагает PR для GitHub Actions и Docker. Обновления
  JavaScript-зависимостей с текущим pnpm 11 пока проверяются вручную.

Приоритет: ограничение попыток входа — ближайший самостоятельный security
патч после проектирования и тестов; остальное — низкий приоритет или требует
отдельной проверки совместимости. Этот аудит сам по себе не делает текущую
сборку «enterprise-безопасной» и не является основанием для релиза.
